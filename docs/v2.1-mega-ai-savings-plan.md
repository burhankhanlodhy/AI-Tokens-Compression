## 1. Objective

Evolve the proxy into a multi-strategy AI savings engine for ordinary applications and tool-heavy, multi-turn coding agents. Strategies must be independently measurable, tenant/session safe, feature-flagged, reversible, and reported using real provider usage or avoided-call evidence. No research or vendor percentage is a product guarantee.

The product must optimize three distinct axes without double counting:

1. Input reduction: lossless cleanup, deferred tool definitions, incremental file context, bounded tool output, and eventually conversation-context reduction.
2. Output reduction: existing quality-gated conciseness and reasoning controls, extended with conservative adaptive budgeting only after measurement.
3. Call and price avoidance: provider-native cache usage, existing semantic-cache gate, and routing/cascade discovery. These remain separately attributable from token transforms.

## 2. Audited baseline and disposition

Already implemented or governed by existing contracts:

- L1 deterministic cleanup, including cache-key-on-clean-bytes behavior and pinned corpus evidence.
- LLMLingua-2 lossy compression with task/protocol safety gates; no new enablement without quality evidence.
- Coding-agent file trimming, import deduplication, shell/debug filtering, tool-schema minification, and bounded tool-result optimization.
- Output conciseness and model-family reasoning controls, including default-off and grounded-quality gates.
- Provider-native cache controls and returned usage attribution from V2.0; exact-prefix tracking; semantic response cache implementation remains off by default and QA-gated.
- Provider dispatch and routing/cascade discovery controls where present; routing is not a production default or a release savings claim.

Gaps to close in V2.1:

- Tool search/deferred loading: current path sends available tool schemas up front.
- Tool Output Continuation Protocol (TOCP): current truncation has no session-bound lazy retrieval of omitted output.
- Incremental Diff Context Protocol (IDCP): repeated file reads send snapshots rather than versioned unchanged notices/diffs.
- Adaptive Turn-Budget Allocator (ATBA): caps are primarily static and do not reserve context by turn intent or react to insufficiency.
- Adaptive output/reasoning budget policy: current controls are not a measured, task-aware budget allocator.
- Multi-Turn Conversation Compression (MTCC): no general relevance-aware history compression with exact source retrieval.
- Strategy orchestration: one policy surface must expose status, evidence, fallback, and per-strategy attribution without combining overlapping denominators.

## 3. Product guardrails and decisions

The execution graph assumes the following conservative scope. A scope change affecting architecture, tenant isolation, provider behavior, default enablement, or quality tolerance must be recorded by Product Manager and escalated to the owner before implementation proceeds.

- Every new lane is server-side feature-flagged and disabled by default until its own quality gate passes.
- Existing clients cannot enable risky lanes through an arbitrary request header or query parameter.
- Every lane has a full-context/full-output escape hatch and deterministic fail-open behavior where applicable.
- Session stores are bound to tenant, API key scope, and session; no cross-tenant or cross-session retrieval is permitted.
- Original tool output, file versions, and conversation turns remain available for bounded retrieval while their TTL is active; omission is never irreversible without an explicit retention policy.
- Cache savings, transform savings, and avoided-call savings remain separate fields and are never summed as independent addends.
- Reported savings include transformation, classifier, summarizer, retrieval, retry, and fallback costs where applicable.
- Market figures such as VS Code's tool-search result, IBM's pointer result, RouteLLM results, or LLMLingua ratios are research context only, not acceptance criteria.
- No release occurs without the final QA GO on the exact release candidate. QA NO-GO leaves release blocked.

## 4. Strategy specifications and acceptance criteria

### A. Tool search / deferred loading

Expose a compact, cache-stable catalog of tool names/descriptions and load full schemas only when the selected provider/client contract supports it. Preserve exact schemas, required fields, tool-call protocol, ordering requirements, and a deterministic fallback to current eager loading. Measure schema tokens, search misses, tool-call failures, retries, latency, and task success. Do not claim a saving when the provider does not support deferred semantics.

Minimum gate: provider compatibility matrix and contract tests for each supported adapter; no protocol regressions; paired workload evidence showing net request-token reduction after search overhead; quality regression within the shared 3 percentage-point target or an explicitly ratified stricter gate; default remains off until QA.

### B. TOCP: Tool Output Continuation Protocol

When an eligible result exceeds the current cap, store the complete result in a TTL-bounded, session/tenant-scoped continuation store. Return a bounded summary/preview, omission metadata, opaque continuation ID, and available bounded segments. Register a safe retrieval path that returns only the requested segment/range; never re-run the original command merely to recover omitted output. Preserve status, errors, exit code, and authorization context.

Minimum gate: deterministic tests for text, JSON, pytest/compiler logs, missing/expired IDs, malformed ranges, tenant/session isolation, and cleanup; replay evidence on at least 50 over-cap results; compare baseline truncation and full-output controls; zero isolation failures; non-inferior task success; record fetch, rerun, and net-token rates.

### C. IDCP: Incremental Diff Context Protocol

Maintain a session-scoped file ledger with canonical path, content hash, immutable version ID, and content. Send full content on first read, an explicit unchanged record when the hash is unchanged, and a base/new-version unified diff when changed. Include path and base version in every diff. Fall back to full content when the diff exceeds a conservative threshold, context cannot be applied, the model requests full context, or validation indicates risk. Never apply a stale diff silently.

Minimum gate: deterministic tests for first read, unchanged read, small change, large change fallback, deletion, rename policy, stale base, concurrent modification, reconstruction, and syntax/test validation; offline token accounting; paired replay on at least 50 representative multi-edit sessions; at least 30% reduction in repeated-file-context tokens, no more than 3 percentage points task-success regression, and no silent stale applications. Whole-session savings must be reported separately.

### D. ATBA: Adaptive Turn-Budget Allocator

Run a conservative, local, explainable turn classifier for exploratory, implementation, debugging, and verification work. Adjust file/tool caps and preserve a session reserve; use neutral current defaults when uncertain. Start in shadow mode, then enforce only with bounded escalation when the model reports insufficient context. Include all retry/escalation and classifier costs in net accounting. Add adaptive output/reasoning budgets as a separate policy dimension, respecting explicit client controls and provider/model restrictions; do not force concision on quality-sensitive turns.

Minimum gate: shadow evaluation on at least 100 sessions, then paired enforcement simulation; net token/cost improvement after retries and policy overhead; no more than 3 percentage points task-success regression; bounded escalation and user/config override; provider-specific reasoning controls remain fail-open; no default-on output budget change without quality evidence.

### E. MTCC: Multi-Turn Conversation Compression

Retain recent working turns verbatim. Score older turns using coding-relevant entities such as files, symbols, errors, decisions, and unresolved constraints. Compress medium-relevance turns into inspectable structured facts, collapse low-relevance filler, retain originals in a session store, and retrieve exact source turns on demand. Never remove unresolved errors, user constraints, or referenced tool results without a retrieval path.

Minimum gate: deterministic retention/retrieval and tenant/session tests; replay at least 30 sessions of 10 or more turns; include summarizer cost and latency; at least 30% context reduction on the tested long-session population, no more than 3 percentage points task-success regression, and no increase in wrong-file/wrong-error diagnoses. Remain off by default if the gate is inconclusive.

### F. Existing lanes and strategy orchestration

Create one strategy registry/policy surface that reports per-lane eligibility, reason, version, fallback, and evidence dimensions while preserving existing L1, output, cache, semantic-cache, and routing contracts. The registry must not hide disabled/gated lanes or convert research estimates into savings. Ledger aggregation must retain separate denominators and distinguish token reduction, provider discount usage, transform compute, and avoided completion.

Minimum gate: contract-level regression suite for existing V2.0 acceptance criteria; per-strategy telemetry and feature-flag audit; no double counting at row, bucket, provider, tenant, and key aggregation levels; rollback restores the previous request path.

## 5. Execution sequence

1. Product Manager ratifies this scope, defaults, quality gates, and the decision that risky lanes remain experimental/off by default.
2. Database Administrator defines the smallest Postgres-first schema/retention changes for session stores, continuation records, version ledgers, policy telemetry, and non-overlapping savings attribution. No speculative migration.
3. Application Developer establishes shared strategy interfaces, feature flags, authorization/session boundaries, telemetry, and regression fixtures.
4. Application Developer implements TOCP, then IDCP. These are independent lanes but both depend on the shared contracts and instrumentation.
5. Application Developer implements tool search/deferred loading and prefix-stable policy with provider compatibility fallback.
6. Application Developer implements ATBA, including the adaptive output/reasoning policy in shadow mode first.
7. Application Developer implements MTCC after exact retrieval and telemetry are available.
8. QA Lead runs independent unit, integration, replay, security/isolation, performance, and regression validation on the exact combined candidate; QA publishes GO or NO-GO with reproducible evidence.
9. Product Manager independently verifies the QA handoff and exact candidate SHA, then performs final push/release only after QA GO. NO-GO keeps the release card unresolved and returns concrete fixes.

## 6. Evidence contract

Every experiment records baseline and treatment on the same population, commit/fixture identity, provider/model/tokenizer, input and output tokens, upstream request count, cache read/write usage where available, transform/classifier/summarizer overhead, latency, fallback/retrieval/retry rates, task success, and confidence intervals. A bill-saving claim requires fewer billable tokens, observed provider discount usage, or an avoided upstream completion. Component percentages are never stacked to manufacture a total; combined treatment is measured directly.

## 7. Release checklist

- All enabled behavior is behind reviewed server-side flags with rollback settings.
- Existing V2.0 contracts and pinned publication literals are unchanged unless a documented gap and QA evidence justify a change.
- Tenant, API-key, session, cache, continuation, and file-version isolation tests pass.
- Baseline and combined-treatment cost/token evidence is attached; research estimates are clearly labeled.
- QA reports GO for the exact candidate SHA. A NO-GO blocks release.
- Product Manager verifies the candidate, updates changelog/release metadata, and pushes only after GO.
