Scope: supported registry rows in `token-saver/proxy/providers/registry.py`.
This is an implementation audit, not a pricing claim. Cache savings are not
inferred from a request control, model, provider, or market discount table.

## Confirmed closure and boundary

The verified request-side gap was the Anthropic adapter's system-prefix cache
control: a stale comment claimed that cache-control blocks were emitted, but
the actual wire body contained a plain string. The adapter now emits one
Anthropic text block with ephemeral cache control for the stable system
prefix; contract tests pin that shape. No other message is marked, and empty
system prompts remain omitted.

The adapters already normalize provider-returned cache read usage (and
Anthropic cache-write usage) for ordinary and streaming responses. OpenAI
compatible usage is passed through in the provider response shape; Anthropic
usage is normalized to OpenAI-compatible `prompt_tokens_details.cached_tokens`
by the proxy response translator. Missing cache evidence remains zero. This
audit makes no provider pricing assumptions and does not claim a dollar-saving
figure. The request ledger's separate dollar attribution is subject to the
V2.0 DBA audit; do not present token counts as dollar savings.

## Preserved contracts

- L1 and output-conciseness code, fixtures, and publication thresholds are
  unchanged; this task found no demonstrated gap in those paths.
- Semantic-cache implementation, keys, flag, and attribution are unchanged.
- `provider_routing` remains server-configured and false by default. It is
  existing provider selection, not a cascade experiment; no V2.0 routing
  savings claim, dashboard value, or production enablement is introduced.
- No vendor/market percentage is used as project evidence or an acceptance
  threshold.
