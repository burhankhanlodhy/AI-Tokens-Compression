## 2. Baseline evidence (live proxy, `/api/kpis`, 2026-09-25)

- 256 of 258 requests take `passthrough`; lossy savers never run on agent traffic (`tools` present on every opencode request).
- `cost_saved / input_tokens_saved` = $2.943 / 5.886M = **exactly $0.50/M** = fallback price. Cause: ledger model `glm-5.3-flash` vs. `pricing.json` key `z-ai/glm-5.3-flash` (exact-match lookup in `config.estimate_cost`).
- Provider-reported cached tokens exceed the proxy's own count of tokens sent → `count_messages` omits `tools` schemas and `tool_calls` arguments.
- Output ≈ 41–44 tokens/turn → counted locally from streamed text; reasoning and tool-call arguments missing.
- Exact/semantic cache hit rate 0% (agent requests never repeat); semantic lane still pays an embedding call per request.
- Error rate ~2.7%, p99 latency > 70 s.

All figures are one workload / one model. No savings percentage is a commitment until the Phase 0 replay has run.

## 3. Replay methodology

### 3.1 What gets recorded (per turn)
`session_id`, `turn_idx`, `ts`, client request body exactly as received (pre-transform), request body exactly as sent upstream (post-transform), provider `usage` object verbatim (incl. `cost`, `prompt_tokens_details.cached_tokens`, cache-write, reasoning tokens), upstream provider name, model as returned, HTTP status, latency, response body.

Session identity: explicit header if the client sends one, else hash of (system prompt + first user message + client key).

### 3.2 Two kinds of test — do not mix them
1. **Offline replay (deterministic)** — valid only for transforms that do not change what the model sees semantically: provider pinning, cache keys, tool-schema ordering, content-derived IDs, session-level routing. Recorded outputs are replayed as-is; the simulator only re-prices input under a cache model. Cheap, repeatable, no API spend.
2. **Live A/B on a fixed task suite** — required for anything that can change model behaviour: output-lever instructions, reasoning caps, compression, compaction. Outputs vary run to run, so each arm runs the same tasks **≥ 5 times**; compare means with spread, not single runs. Report task completion, turns, re-reads, and cost per completed task.

Offline replay must never be used to claim savings for a behaviour-changing transform.

### 3.3 Cache model inside the simulator
- Cache hits modelled by **longest common prefix** with the previous request on the same (provider, model), in the provider's block granularity.
- **TTL measured, not assumed:** from recorded data, bucket consecutive-turn gaps and plot provider-reported cached share vs. gap; the drop-off point is the working TTL. Same for cache-read price (from `usage.cost` vs. token mix).
- Original inter-turn timing and provider sequence are preserved.
- Validation: simulator's predicted cached tokens for the *unmodified* baseline must match provider-reported cached tokens within **±5%** before any variant result is trusted.

### 3.4 Calibration gate for the ledger
- Local input count vs. provider `prompt_tokens`: median error ≤ 2% after including `tools` and `tool_calls`. Until then, provider numbers are ground truth and local counts are labelled estimates.
- Cost: ledger cost vs. provider `usage.cost` within ±2% per day.

### 3.5 Metrics per arm
Cost per completed task split into fresh input / cache read / cache write / output / reasoning; turns per task; re-read count and cost (charged to the transform that caused it); stable-prefix length vs. provider-cached tokens; error and retry cost; p50/p95/p99 latency. Dashboard shows three separate lines: provider baseline, proxy-caused savings, total verified savings.

### 3.6 Gates
- **Phase 0 exit:** §3.3 and §3.4 validations pass on ≥ 1 week or ≥ 20 sessions of recorded traffic, whichever comes first.
- **Phase 1 claim:** only the cache-hit *increase* (pinning on vs. off, same sessions) counts as proxy savings.
- **Phase 3 entry:** replay shows safely removable tool-result text ≥ ~15% of spend at post-cache prices.

## 6. Fixed task suite (Phase 2 live A/B)

Definition: `token-saver/benchmark/task_suite/tasks.json` (v1, pinned to base commit `0c7a595`).
Validator: `token-saver/benchmark/task_suite/validate_suite.py` — for each task, in a throwaway worktree, checks that the guard passes at base, the setup applies, `check` **fails** after setup (it's a real task), and the reference fix makes `check` + guard **pass** (it's solvable). Current result: **5/5 admissible**.

| ID | Kind | What the agent must do |
|---|---|---|
| fix-01-l1-null-dropped | bugfix | L1 cleaner drops `null` fields; restore null conservation |
| fix-02-empty-tool-calls-not-protocol | bugfix | `tool_calls: []` no longer treated as protocol state |
| fix-03-cost-rates-swapped | bugfix | input/output rates swapped in `estimate_cost` |
| fix-04-tocp-range-off-by-one | bugfix | TOCP half-open range returns one char short |
| feat-05-tocp-delete | feature | add scoped, thread-safe `ContinuationStore.delete` with tests |

Run protocol:
- Every run starts from a fresh worktree at the base commit with `setup` applied. The agent sees only `prompt`, never `check`, `hidden_test` or `reference_fix` (hidden tests are written only after the agent stops).
- **Completed** = every `check` command and the regression `guard` exit 0.
- Limits: 40 agent turns and 20 min wall time per run; exceeding either = not completed (cost still counted).
- ≥ 5 runs per task per arm; arms interleaved (A,B,A,B…) rather than blocked, so time-of-day provider effects hit both arms equally.
- Same model, same client (opencode) version, same proxy build except the flag under test.

Limitation: 5 tasks on one repo is small. It detects large effects (roughly ≥ 20% change in cost per completed task); smaller effects need more tasks or runs. Tasks may be added in a v2 of the file, never edited in place once a run has used them.

## 7. Replay input schema

Proposal for the DBA (owner of the 2026-09-29 recording deliverable). One row per upstream attempt, so retries are visible.

```sql
CREATE TABLE replay_turns (
  id                    bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  session_id            text        NOT NULL,  -- header value, else sha256(system + first user msg + key id)
  session_id_source     text        NOT NULL CHECK (session_id_source IN ('header','derived')),
  turn_idx              integer     NOT NULL,  -- 0-based per session, one per client request
  attempt               smallint    NOT NULL DEFAULT 1,  -- >1 = retry of the same turn
  ts_request            timestamptz NOT NULL,
  ts_first_byte         timestamptz,
  ts_done               timestamptz,
  tenant_id             uuid        NOT NULL REFERENCES tenants(id),
  request_id            bigint      REFERENCES requests(id),  -- join to the existing ledger
  model_requested       text        NOT NULL,
  model_returned        text,                 -- as reported by the provider
  upstream_provider     text,                 -- e.g. OpenRouter `provider` field
  experiment_arm        text,                 -- NULL for organic traffic
  body_client           jsonb       NOT NULL, -- as received, after secret redaction
  body_upstream         jsonb       NOT NULL, -- as sent, after secret redaction
  body_upstream_sha256  text        NOT NULL, -- hash of exact bytes sent, BEFORE redaction
  response_body         jsonb,                -- assembled final message incl. tool_calls
  usage_raw             jsonb,                -- provider `usage` object verbatim
  http_status           integer     NOT NULL,
  error_kind            text,
  fallback_event        boolean     NOT NULL DEFAULT false,  -- D3 cache_loss marker
  redaction_count       integer     NOT NULL DEFAULT 0,
  UNIQUE (session_id, turn_idx, attempt)
);
CREATE INDEX ON replay_turns (ts_request);          -- 30-day retention sweep
CREATE INDEX ON replay_turns (session_id, turn_idx);
```

Notes:
- `usage_raw` is stored verbatim; all derived fields below are computed at read time, so a parsing bug never corrupts recorded data.
- Streaming requests must send `stream_options.include_usage = true` upstream so `usage_raw` is populated; a turn with `usage_raw IS NULL` is excluded from calibration and counted in the exclusions report.
- The simulator computes common-prefix length on the canonical serialization of `body_upstream` (keys in original order, compact separators). Redaction replaces a secret with a fixed-length placeholder so byte offsets for prefix matching are preserved.
- Retention: `DELETE FROM replay_turns WHERE ts_request < now() - interval '30 days'`, run daily.

## 8. Metric formulas

Notation, per turn *t* (from `usage_raw`; field names are OpenRouter/OpenAI-compatible, adapters map others onto them):

| Symbol | Source |
|---|---|
| P_t | `prompt_tokens` |
| C_t | `prompt_tokens_details.cached_tokens` (0 if absent) |
| W_t | `prompt_tokens_details.cache_write_tokens` (0 if absent) |
| O_t | `completion_tokens` |
| R_t | `completion_tokens_details.reasoning_tokens` (0 if absent; R_t ⊆ O_t) |
| $_t | `usage.cost` (provider-billed USD) |
| p_in, p_cr, p_cw, p_out | per-token prices: fresh input, cache read, cache write, output |

**Cost decomposition** (per turn; must reconcile to $_t):
- fresh input = (P_t − C_t − W_t) · p_in
- cache read  = C_t · p_cr
- cache write = W_t · p_cw
- reasoning   = R_t · p_out
- visible output = (O_t − R_t) · p_out
- reconciliation error = |Σ parts − $_t| / $_t. Gate §3.4: daily aggregate ≤ 2%. If p_cr is unknown, estimate it by least squares of $_t on (P_t − C_t, C_t, O_t) over the recorded turns; that estimate is the "measured cache-read price" reported on 2026-10-07.

**Per task / session** (sum over all turns and all attempts, including failed ones):
- cost_task = Σ $_t
- **cost per completed task (headline, D1)** = Σ cost over all runs in the arm ÷ number of completed runs. Failed runs' cost stays in the numerator.
- turns_task = number of distinct `turn_idx`
- retry cost = Σ $_t over rows with attempt > 1, plus the rows whose http_status ≠ 200
- cache hit ratio = Σ C_t ÷ Σ P_t

**Re-reads** (charged to the transform in effect): a re-read is an assistant tool call whose (tool name, canonical JSON arguments) equals an earlier call in the same session **and** whose earlier result the proxy modified (compressed, truncated, or continued via TOCP). Re-read cost = $ of the turn that issued the call plus the $ of the next turn (which carries the re-read result). Identical calls to results the proxy did not touch are counted separately as `natural_repeat` and not charged to any transform.

**Stable prefix**: S_t = length in tokens of the longest common prefix of `body_upstream` at turns t−1 and t (same session, same upstream_provider). Reported alongside C_t; if C_t < 0.9 · S_t while the gap is below the measured TTL, the provider is not caching what it could, and that gap is attributed to the provider, not the proxy.

**Calibration gates**:
- Simulator: |Σ Ĉ_t − Σ C_t| / Σ C_t ≤ 5% on the unmodified baseline, where Ĉ_t is the simulator's predicted cached tokens.
- Local counter: median over turns of |P̂_t − P_t| / P_t ≤ 2%, where P̂_t is the proxy's local count including `tools` and `tool_calls`.

**TTL estimate**: bucket turn pairs by gap Δ = ts_request(t) − ts_done(t−1) (buckets 0–30 s, 30–60 s, 1–2 min, 2–5 min, 5–10 min, 10–30 min, 30–60 min, > 60 min). For each bucket compute Σ C_t ÷ Σ S_t. The working TTL is the upper edge of the last bucket whose ratio is ≥ 0.5 × the ratio of the 0–30 s bucket.

**Arm comparison (Phase 1 and 2)**:
- Effect = (cost per completed task in B − in A) ÷ in A.
- Uncertainty: 95% bootstrap confidence interval, resampling runs within each task (stratified by task), 10,000 resamples.
- **Ship rule**: the CI upper bound is < 0 (a real saving), **and** the completion rate in B is not lower than in A by more than 1 run in 25, **and** p95 latency in B is ≤ 1.1 × A.
- Phase 1 proxy-caused savings = Σ over sessions of (C_t^pinned − C_t^unpinned) · (p_in − p_cr), from the offline replay, minus the cost of `fallback_event` cache losses.
