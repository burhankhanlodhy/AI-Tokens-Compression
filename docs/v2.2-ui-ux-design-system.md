## 1. Design principles & explicitly avoided anti-patterns

### 1.1 Principles

1. **Ledger-honest.** Every displayed NUMBER is copied 1:1 from an API field. Zero client-side aggregation (PM §1.2 invariant AC-A8; dashboard.js:1-2). The only permitted client-side math is (a) bar/geometry widths and (b) array-length counts of returned arrays (precedent: dashboard.js:88-95 version-disagreement count). No arithmetic on scalar fields, ever.
2. **Modes are not measurements.** A disabled feature renders an `off` badge and "—", never 0/0% (dashboard.js:65-101). Three states are always distinguished: off (mode), warming (on, no qualifying rows yet), live (on, ≥1 qualifying row).
3. **Contained decomposition, never summed.** L1 / exact-cache / semantic-cache sub-tiles annotate the headline; they are per-request categories and are never added together (a1eae90 contract, dashboard.js:35-63). Every decomposition surface carries the muted containment note in the card itself.
4. **The UI is a dumb renderer of server truth.** Gate logic, precedence, and allowlists live server-side (PM B2). The UI never computes whether a control is writable; it renders a server-supplied lock state (§6.5.2, deviation D-3).
5. **State honesty over polish.** Loading = skeletons, empty = guidance + one CTA, error = inline retry that never destroys form/confirm state (dashboard.js §4.4), degraded = per-card failure, never a full-page blank (PM §4).
6. **One component set, all surfaces.** Every tab composes the same cards, badges, tables, buttons, and state blocks from §4. No per-tab reinvention.

### 1.2 Anti-patterns — explicitly forbidden in V2.2

| Anti-pattern | Rule |
|---|---|
| Generic "AI dashboard" chrome | No hero banners, gradient text, glowing borders, animated backgrounds, marketing copy. This is an operator console. |
| Excessive gradients / glassmorphism | No backdrop-blur, no translucent layered panels, no gradient fills on cards. The only gradient allowed is the existing skeleton shimmer (dashboard_v2.py:51-57). |
| Over-rounded surfaces | Max radius is 10px (cards). No pill-shaped cards, inputs, or tables. Pills (999px) only for badges/chips. |
| Disconnected toggles | Every switch must (a) show its effective source (runtime/env/default), (b) persist via the settings API with feedback, and (c) render locked when the server says so. A toggle that flips visually without a confirmed write is a release blocker. |
| Decorative charts | Every chart maps to a named API series field (§6). No chart may be fabricated from scalars, and no latency line chart exists because the contract exposes only window-global percentiles (dashboard.js:283-286 precedent). |
| Renaming layer | Badge/label text is the verbatim API/ledger string (cache statuses, tripwire statuses, fallback names). No friendly renaming — QA reconciles UI ↔ ledger directly (dashboard.js:171-176). |
| Silent failure | No catch-and-render-previous-numbers. Any fetch failure replaces the affected card's body with the shared error block. |
| Secret-adjacent display | No upstream BYOK key fields anywhere (PM §3.4 — a mock containing one is a spec violation). Proxy keys render last4 only; `key_hash` never rendered; admin token never rendered outside its password input. |

### 2.3 Spacing, radius, elevation

- Spacing scale (rem): 0.25 / 0.5 / 0.75 / 1 / 1.5 / 2 / 3. Card padding 1rem; grid gap 12px (existing); section gap 1.5rem.
- Radius: 6px controls/buttons/inputs, 8px subtiles, 10px cards/error boxes, 999px badges/chips. Nothing else.
- Elevation: none (no box-shadows). Layering is communicated by `--panel-raised` + `--border` + scrim for overlays.
- Focus ring NEW: `:focus-visible { outline: 2px solid var(--accent); outline-offset: 2px; }` on every interactive element. (The V2.1 shell defines no focus style — this is a required fix, not an option; see I-9.)

### 2.4 Iconography

No icon font, no emoji in status roles. Status is color + verbatim text. The only glyphs permitted: `▲ ▼` (existing delta arrows, dashboard.js:248), `••••` key mask (dashboard.js:439), "—" mode marker, and a lock indicator rendered as the text `locked` inside a neutral badge (no padlock emoji). Chart legends and badges always pair color with text (never color-alone).

## 3. Component library (single source — every tab composes these)

Each component lists its states. Class names extend the existing shell set (dashboard_v2.py:38-108); NEW marks additions.

1. **Card** `.card` + `.span3|.span6|.span12` — container for everything. Header `.card h3`. States: normal; degraded (body replaced by error block); loading (body replaced by skeleton rows).
2. **KPI card** — `kpiCard()` pattern (dashboard.js:23-29): label, numeral, optional delta line, optional sparkline. Numeral renders "—" when the source field is null/absent.
3. **Sub-tile** `.subtile` — contained decomposition unit inside a parent card, with `.lead` label and `.subrow` rows; zero-state variant `.subtile.l1-zero` renders "—" + plain-language absence note (existing dashboard.js:40-63, 103-116).
4. **Badge** `.badge.{green,red,gold,neutral}` — verbatim status text only.
5. **Chip** `.chip` — static metadata (scopes, adapter_class). Not interactive.
6. **Source chip** NEW `.chip.source-runtime|.source-env|.source-default` — attached to every settings value (AC-D3): text exactly `runtime`, `env`, or `default` from the API `source` field (PM §5.2). `runtime` gets accent border; the others are neutral. A settings value without a visible source chip is a defect.
7. **Button** `.btn` (primary), `.btn.ghost`, `.btn.danger`, `:disabled` at opacity .5 with `cursor:default` (existing). Min height 32px desktop / 44px coarse pointers (§5). Busy state NEW: during an in-flight write the triggering button is disabled with its label suffixed "…" (precedent: "Creating…", dashboard.js:679).
8. **Input** `.form-input` (+`type="password"` for tokens), **select** (native `<select>`, styled per dashboard.js:766), **switch** NEW: a native `<input type="checkbox" role="switch">` styled as a track/thumb — native element so keyboard/focus/screen-reader semantics are free; visually: 36×20px track, border `--border`, thumb `--muted`; checked: track `--accent`, thumb `--text`; disabled: opacity .5; locked: disabled + `locked` badge adjacent.
9. **Table** — existing style (dashboard_v2.py:48-50); wrapped in `.table-scroll` NEW (overflow-x:auto) so narrow viewports scroll the table instead of breaking layout. Row click targets (usage drawer) get `cursor:pointer` and a visible `:focus-visible` style; rows that open the drawer are `<tr tabindex="0" role="button">` NEW (keyboard parity, §7).
10. **Chart wrapper** `.chart-wrap` (260px) — Chart.js 4 from the existing CDN script tag (dashboard_v2.py:19; no build step, PM §7.1). Line charts use the existing scale colors (dashboard.js:208-209). Doughnut palette: `--accent, --green, --gold, --red, --violet, --cyan` in that order (existing, dashboard.js:275).
11. **Skeleton** `.skel`, `.skel-row` (existing shimmer). Loading never shows spinners-in-void.
12. **Error block** `.error-box` (existing) — message + `Retry` button; retry re-fires the failed fetch only (precedent: harness fail-fetch mode asserts the refire). Never a silent fall-back.
13. **Empty state** `.empty` — per-tab copy (§6); one CTA max.
14. **Confirm inline** — the existing two-tap destructive pattern (dashboard.js:412-431): first tap converts the action into `Confirm <verb>?` + `Cancel` + consequence hint; untouched confirms revert after 5s (dashboard.js:597-604). Used for revoke/rotate and NEW for settings override revert.
15. **Token prompt** — the existing admin-token card (dashboard.js:489-495): password input, module-variable storage only, never storage/URL/log (dashboard.js:334, 715). Shared by Keys, Settings, and any 401 surface. On 401 the pending action is preserved and replayed after token entry (§4.5.4, dashboard.js:626-657 — this rule is GENERALIZED to all writes including settings PUT/DELETE, per PM AC-Q4).
16. **Drawer** — the key-usage drawer pattern (dashboard.js:470-487) promoted to a shared component NEW: `.drawer` fixed right panel (max-width 420px, full-height, `--panel-raised`, scrim `--overlay`), `Esc` closes, focus moves to the drawer heading on open and returns to the invoking row on close. V2.2 keeps the existing inline drawer rendering under the keys table as the ≤900px fallback (see §5.4); on desktop the usage drawer MAY render as the side panel — implementation choice, one of the two, not both.
17. **Banner** NEW `.banner.warn` — full-width, gold border/text, used for the G2 hosted-mode warning (§8) and the G1 benchmark-scope note (§6.5.4). Dismissible per page-load (no persistence) via a ghost `Dismiss`; dismissal is visual only and resets on reload.
18. **Persistence feedback** NEW `.save-note` — inline muted text adjacent to the control: `Saving…` → `Saved — effective immediately` (2s, then clears) or the inline error. Never a toast stack; feedback lives next to the control it belongs to.

## 4. Shell, navigation, routing

### 4.1 Structure (unchanged model, extended)

Single-page shell, hash routing, no framework, no build step (PM §2, §7.1). Routes: `#overview` `#traffic` `#providers` `#keys` `#settings` (new). Unknown hashes fall back to overview (dashboard.js:753 precedent). The shell template gains one nav anchor and keeps Chart.js CDN.

Nav order (left→right): brand `token-saver` · Overview · Traffic · Providers · Keys & Tenants · Settings · spacer · bucket selector · `#prov-status` slot.

- **Bucket selector** (minute/hour/day, existing dashboard.js:764-768) scopes every KPI-backed tab (Overview, Traffic, Providers, Keys usage drawer). It is hidden on the Settings tab NEW — Settings data (settings list, strategy flags, tripwire) is not bucket-scoped, and showing a control that does nothing is a disconnected-toggle violation. Tripwire keeps its server default window (PM §1.1 `/api/tripwire`); the card labels its window honestly ("last N days" from the endpoint's `days` default — rendered only if the response carries it, else no window claim).
- **`#prov-status`** slot: unchanged.

### 4.2 Grid

12-column grid (dashboard_v2.py:37). Card spans per screen in §6. Max content width 1200px centered (dashboard_v2.py:36).

### 4.3 Responsive behavior — resolves PM open decision #1 (mobile IA)

**Decision: scrollable top tab strip; no hamburger, no bottom bar.**

Rationale: the dashboard is an ops console whose primary surface is desktop/laptop; mobile is glance-and-triage. A horizontally scrollable top tab strip (a) keeps one `<nav>` DOM across all breakpoints — critical because the render harness executes the same DOM bindings (dashboard_render_harness.js), (b) preserves native anchor keyboard/screen-reader semantics with zero JS, (c) avoids `position:fixed` bottom-bar safe-area and viewport bugs, (d) keeps the IA visible in one gesture instead of hidden behind a hamburger (two taps, worse discoverability for 5 items).

Breakpoints (binding):

| Width | Class | Behavior |
|---|---|---|
| ≥1201px | desktop | As today: 12-col, span3/6/12 per §6. |
| 901–1200px | laptop | Unchanged grid (max-width 1200 already constrains). Nav fits without scrolling. |
| 561–900px | tablet | Existing rule kept (dashboard_v2.py:109): span3→span6, span6→span12. Nav becomes a horizontally scrollable strip: `nav { flex-wrap: nowrap; overflow-x: auto; }`, each tab link min-height 44px, `white-space: nowrap`. Bucket selector stays in the strip. |
| ≤560px | mobile NEW | All spans → span12. KPI numeral drops to 1.5rem. Tables scroll inside `.table-scroll`. Nav strip scrolls; brand collapses to `ts` NEW (`.brand` full text hidden, 2-letter mark shown) to give tabs room. Bucket selector drops into the strip as its last item. Confirm buttons stack vertically (full-width) inside table action cells. |

Touch targets ≥44×44px at ≤900px for nav links, buttons, switches, and clickable rows.

## 5. Global interaction patterns

### 5.1 Write pattern (all writes: keys, settings)

Reuse `doWrite` (dashboard.js:626-657) generalized:
1. Bearer attached only after token entry; token lives in a module variable only.
2. 401 → clear token, render the shared token prompt, preserve the pending action AND any confirm state, replay on save.
3. Non-401 failure → inline error into a pre-rendered slot; NO re-render (form/confirm state survives).
4. Success → targeted re-fetch of the affected collection (settings list / keys list), never a blind full reload that loses scroll position on other tabs.

### 5.2 Settings write lifecycle (P1 flow, PM §4)

Toggle/PUT sequence per control:
1. User flips switch → switch disables, `.save-note` shows `Saving…`.
2. `PUT /api/settings/{name} {value}` with bearer.
3. 200 → re-read the item from the response (effective value + source), set switch to the returned value, source chip updates to `runtime`, `.save-note` shows `Saved — effective immediately` for 2s. The rendered value always comes from the server response, never from the click (pessimistic, not optimistic).
4. 400 (unknown/not-runtime) → switch reverts to prior value, inline error carries the server's field-named message (B-10 convention, kpis.py:285-291).
5. 401 → token prompt; the pending PUT replays after entry (§5.1.2).
6. 503 → switch reverts, inline error `ledger unavailable` style message with a `Retry` button scoped to that control.
7. Revert path: when `source == "runtime"`, a ghost `Revert` button appears beside the control → same two-tap confirm as destructive actions → `DELETE /api/settings/{name}` → source chip returns to `env`/`default`.

### 5.3 Reads

- Overview/Traffic/Providers: one `/api/kpis?bucket=…[&from&to]` fetch (existing). Providers additionally fetches `/api/providers` (§6.3).
- Keys: `/api/tenants` + `/api/keys?tenant_id=` + scoped `/api/kpis` (existing).
- Settings NEW: three independent fetches — `/api/settings`, `/api/strategies` (ADMIN_TOKEN-gated, PM §1.1), `/api/tripwire` — each feeding its own card with its own skeleton/error/retry. One failing endpoint never blanks the tab (per-card degradation, PM §4).
- Settings does NOT fetch `/api/kpis` and is NOT gated by the zero-traffic empty state NEW: the `!d.overview.requests → emptyState()` hijack (dashboard.js:748) applies only to KPI-backed tabs (overview/traffic/providers). A fresh deployment with zero traffic must still be able to open Settings and flip controls.

### 5.4 State matrix (every tab)

| State | Rule |
|---|---|
| Loading | Skeleton rows mirroring the final layout (card-shaped, not one generic block). |
| Empty | Per-tab copy (§6) with at most one CTA; never zero-padded charts. |
| Error | Shared error block + Retry inside the affected card only. |
| Degraded | Ledger 503 (envelope per kpis.py:321-328) degrades only KPI-backed cards; non-ledger cards (settings list, key inventory) keep rendering. |
| Unauthorized | 401 on any write (or `/api/strategies` read) → shared token prompt with pending-action preservation. |
| Disabled | `disabled` attribute + opacity .5 + adjacent reason text (never a dead control with no explanation). |
| Persistence feedback | `.save-note` pattern, §5.2. |


The seven allowlisted controls (PM §3.1) with their binding copy — label / description / impact-tradeoff line (the third line is REQUIRED; a control that hides its tradeoff is a spec violation):

| Setting | Label | Description | Impact / tradeoff |
|---|---|---|---|
| `l1_enabled` | L1 structural cleanup | Lossless deterministic cleanup of coding-agent context, runs before caching. | Saves tokens on structural noise; an entire-message pretty-printed JSON body gets whitespace-compacted (documented caveat, config.py:126-137). |
| `tool_schema_minify` | Tool-schema minification | Minifies validated tool schemas before forwarding. | Lossless on validated schemas; unvalidatable schemas forward verbatim (main.py:652 per PM §3.1). |
| `tool_schema_cache_enabled` | Tool-schema cache | Reuses minified schemas across requests; subordinate to the master cache switch. | No wire-shape risk; disabling costs repeat tokens on schema-heavy traffic. |
| `tool_result_optimization` | Tool-result optimization | Filters/truncates completed tool results before upstream forwarding. | Output-side only; assistant envelopes stay byte-preserved (PM §3.1). |
| `tool_result_compression_enabled` | Tool-result compression | Lossless compression for the tool-result class only. | Savings on verbose tool output; never touches assistant message envelopes. |
| `output_conciseness_enabled` | Output conciseness | Injects a conciseness instruction on long user prompts. | Benchmarked NET-NEGATIVE on short prompts (P1-1); per-request header override keeps precedence over this default (PM §3.1). |
| `semantic_cache_enabled` | Semantic cache | Serves repeated-meaning prompts from the vector cache. | **Gated**: writable only while the AC-PC4/PC5 calibration gate is green. See lock rule below. |

**Semantic-cache lock rule (resolves PM open decision #5): visible-but-locked.** The control always renders. When the server marks it locked (deviation D-3: the settings item carries `locked_reason: string | null`; null = writable), the switch is disabled, a neutral `locked` badge renders, and the `locked_reason` text displays verbatim below the row, followed by a pointer to the tripwire card ("Gate status: see Pipeline health below."). The UI never computes gate state itself (principle 1.1.4). Rationale for visible over hidden: operators must discover the feature exists and why it cannot be enabled; a hidden toggle produces support confusion, a dead-looking unlocked toggle produces 400s.

## 7. Keyboard, focus, accessibility

1. **Focus visible everywhere**: the §2.3 focus ring on links, buttons, inputs, selects, switches, clickable rows. Never `outline: none` without replacement.
2. **Tab order = DOM order = visual order.** Nav → bucket selector → content. No positive `tabindex` anywhere; `tabindex="0"` only on drawer-opening rows.
3. **Hash routing is anchor-based**, so keyboard users navigate tabs as links; on tab change, focus moves to the first heading inside `#content` NEW (`h3`/heading of the first card, `tabindex="-1"`, focus without scroll-jank) so screen-reader users land on the new content, not the stale focus position.
4. **Drawer**: opens with focus to its heading; `Esc` closes; focus returns to the invoking row; scrim click closes. Token prompt: focus lands in the password input on render.
5. **Confirms**: the two-tap confirm is keyboard-equivalent (buttons, not hover); the 5s revert timer must not fire while focus is inside the confirm group NEW (pause-on-focus — a keyboard user tabbing to Confirm must not have it vanish).
6. **Switches** are native checkboxes with `role="switch"` and an associated `<label>` — Space toggles, state announced.
7. **Contrast**: all text/background pairs above meet WCAG AA at their sizes on `--bg`/`--panel` (the existing palette was chosen dark-on-dark-safe; the `.save-note` muted text is the smallest at 0.75rem and stays `--muted` on `--panel` — 4.6:1, passes for its size class).
8. **Color never alone**: every colored status also carries text (badges), every chart series is distinguishable by legend label + tooltip, deltas carry ▲/▼ glyphs.
9. **Motion**: the only animation is the skeleton shimmer; respect `prefers-reduced-motion` NEW by disabling the shimmer animation under that media query (static block, same layout).
10. **Tables**: real `<th scope="col">` headers (existing), no layout tables.
11. **`lang="en"`** already on the shell (dashboard_v2.py:14); keep.
12. **No console errors**: implementation must load with a clean console (implementation card AC).

## 8. Threat model & secret-handling constraints (PM §1.5 G2, §3.4 — binding)

### 8.1 Threat-model note (required by PM §1.5 G2 / AC-D1)

V2.2 keeps management and KPI READS unauthenticated (`/api/tenants`, `/api/keys`, `/api/kpis`, `/api/tripwire`, `/api/settings` GET; PM §1.1, §5.2). This is a deliberate self-host ruling: the proxy is expected to run on an operator-controlled host/network where read visibility of tenant names, key last4s, spend caps, KPIs, and configuration values is acceptable. Writes remain ADMIN_TOKEN-gated everywhere (keys, settings PUT/DELETE, `/api/strategies` read).

Residual risks accepted by this ruling: (a) anyone with network reachability can enumerate tenant/key metadata and spend caps; (b) configuration values (base URLs, model choices) are readable; (c) error messages may echo ledger detail strings (kpis.py:322-328). Mitigations carried by design: no secret material is ever served or rendered (§8.2); the hosted-mode banner (below) flags deployments that drift from self-host; the operator docs must state the binding assumption (AC-R2 territory). Read-auth enforcement stays a non-goal for V2.2 (PM §7.4).

### 8.2 Secret-handling rules for every surface

1. **BYOK invariant**: upstream provider credentials pass through per request and are never stored, displayed, or mocked. The Providers tab shows registry facts only; an upstream-key input anywhere is a spec violation (PM §3.4).
2. **Proxy keys**: render `key_last4` with the `••••` mask only; `key_hash` is never sent by the API and never rendered; plaintext appears exactly once in the reveal panel after create/rotate, with the "shown once" warning and a Copy button whose failure path says "select the text manually" (dashboard.js:545-559).
3. **Admin token**: password input, module variable only, never localStorage/sessionStorage/URL/log (dashboard.js:334, 715); any 401 clears it; `Forget token` clears it.
4. **Component-level redaction**: the deployment-only settings table masks any value whose name matches token/secret/key (§6.5.3), independent of server behavior. Redaction is a property of the component, not an afterthought.
5. **Hosted-mode banner**: when any `/api/tenants` row has `plan != 'self_host'`, the Keys and Settings tabs render `.banner.warn`: "Management and KPI reads are unauthenticated (self-host threat model). This deployment has a non-self-host tenant plan — restrict network access or front the proxy with an auth layer." (PM §3.4 G2 ruling.)
