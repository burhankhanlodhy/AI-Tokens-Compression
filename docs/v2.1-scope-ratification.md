## 2. Ratified scope and explicit defaults (do not re-litigate)

All six lanes are ratified as V2.1 scope, each flag-off by default:

- **A. Tool search / deferred loading** — ratified with the plan's provider
  compatibility gate. Ratification condition: the compact catalog must be
  cache-stable on the provider-native cache key path so enabling it cannot
  degrade V2.0 exact-prefix cache attribution.
- **B. TOCP** — ratified. TTL-bounded, tenant/session-scoped continuation store;
  never re-run an original command to recover output.
- **C. IDCP** — ratified with the unchanged-read notice, versioned diff, and
  full-content fallback ladder as specified.
- **D. ATBA + adaptive output/reasoning budgets** — ratified **shadow-mode
  first, enforcement only after paired evidence**; the adaptive output-budget
  dimension must respect the ratified conciseness contract
  (`output_conciseness_enabled: False` default stands; ATBA does not flip it).
- **E. MTCC** — ratified as the highest-risk lane; verbatim recent turns +
  exact-source retrieval are mandatory, not optional. Off by default unless its
  gate passes; inconclusive gate = stays off (per plan §4.E).
- **F. Strategy orchestration / registry** — ratified. It reports; it does not
  aggregate overlapping denominators. Separate attribution fields stand.

Explicit defaults, restated as binding decisions (they match the plan's §3; I
confirm them as PM rulings so they are not re-argued per lane):

1. **Every new lane is server-side feature-flagged, default OFF.** No request
   header or query parameter can enable a risky lane (same rule as
   `semantic_cache_enabled`, config.py:90-93). The foundation card (t_b29df677)
   implements the flag mechanics; per-lane flags gate their own enablement.
2. **No market/research percentage is an acceptance criterion.** VS Code
   tool-search, IBM pointer, RouteLLM, LLMLingua figures are research context
   only (extends AC-V2-2 to all V2.1 lanes). AC-V2-2's "product constants" rule
   applies to the registry: no research ratio may be encoded as a product
   constant or default.
3. **No release before explicit QA GO on the exact candidate SHA.** Reuses the
   V2.0 AC-V2-5/AC-V2-9 mechanics; the release card (t_fdbd059e) stays blocked
   until QA GO (t_74240231).
4. **Escape hatches are mandatory**: full-context/full-output per lane,
   deterministic fail-open where applicable, per the plan §3.
5. **Isolation is non-negotiable**: continuation stores, file ledgers, turn
   stores are bound to tenant + API-key scope + session. Zero cross-tenant or
   cross-session retrieval; this extends the ratified tenant-quota isolation
   contract to all new stores.
6. **No double counting**: cache savings, transform savings, and avoided-call
   savings remain separate fields and are never summed as addends (extends
   AC-V2-4). The registry reports per-lane evidence; ledger aggregation keeps
   separate denominators at row, bucket, provider, tenant, and key levels.
7. **Omission is never irreversible without a retention policy**: originals
   stay retrievable while TTL is active (plan §3 stands as a hard requirement).

## 3. Amendments to the plan (binding; implementation must follow these)

- **A1 (quality gate is shared, ceiling not floor).** The plan's "3
  percentage-point target" task-success regression bar is ratified as a shared
  ceiling across all six lanes. A lane may adopt a stricter bar; no lane may
  adopt a looser one without a new PM ruling. Baseline task-success measurement
  is defined per lane in its replay evidence (plan §4).
- **A2 (ATBA ordering).** Plan §5 puts ATBA after deferred tools (step 6). Since
  ATBA is shadow-mode-first and independent of the tool lanes, it may start its
  shadow evaluation as soon as the shared foundation (t_b29df677) and DBA
  telemetry contracts (t_cfccc06c) land; only its ENFORCEMENT path waits for
  paired evidence. This is a sequencing relaxation, not a gate change.
- **A3 (research-input traceability).** The four research inputs
  (`algortithm_research1.md`, `gap-analysis-and-novel-techniques.md`,
  `token-saving-techniques-sota-survey.md`,
  `cost-saving-techniques-inventory.md`) are currently untracked in a sibling
  worktree (verified: only t_4ad9540f has them, untracked; zero commits across
  all refs). Before any V2.1 lane cites them as evidence provenance, the plan
  document and the research artifacts must be committed to the repo. The plan's
  "Research inputs" line may not reference files that git cannot recover.
- **A4 (deferred-tools provider matrix is a gate artifact).** The provider
  compatibility matrix (plan §4.A) is a committed QA artifact, not tribal
  knowledge: each supported adapter gets contract tests in-repo, and an
  adapter without deferred-semantics support is recorded as "no claim" in the
  registry rather than silently skipped.

## 5. Evidence contract (carried forward, binding on all lanes)

Plan §6 stands as ratified: every experiment records baseline vs treatment on
the same population, commit/fixture identity, provider/model/tokenizer, token
counts, upstream request count, cache usage where available, transform and
overhead costs, latency, fallback/retrieval/retry rates, task success, and
confidence intervals. Component percentages are never stacked; combined
treatment is measured directly. This matches the ratified V2.0 evidence
contract and the product-spec-authoring statistical-soundness rules (committed
fixtures, pinned checksums, pre-run estimator calibration where an AC depends
on a measured statistical effect — the calibration-gate rule applies to MTCC
scoring and ATBA classification before any paid replay run).
