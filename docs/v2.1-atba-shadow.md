# ATBA local policy and evidence contract

`proxy.atba` provides pure local recommendations for shadow evaluation. It is not
called by the chat forwarding path and never changes a provider payload. The
existing server-side controls remain authoritative: both `v21_atba_enabled` and
`v21_atba_enforce` default to false; do not enable enforcement before independent
QA. Output conciseness remains governed by `output_conciseness_enabled` and ATBA
does not turn it on.

## Turn classifier and caps

`classify_turn(text)` uses explicit local lexical cues for exploratory,
implementation, debugging, and verification turns. It retains no prompt and
emits no logs. Ambiguous or cue-collision input is `unknown` (confidence 0), so
`plan_turn_budget` uses the caller's existing caps. Exploratory recommendations
are modestly smaller; debugging and verification recommendations modestly
larger. Implementation and unknown keep neutral caps. The session reserve is
subtracted from available turn tokens before any recommendation; exhaustion of
the reserve prevents escalation. Only explicit context-insufficiency signals
may produce one bounded escalation (caller passes the session escalation count).
Retry callers must increment that count; no automatic retry is initiated here.

## Adaptive output/reasoning policy

`recommend_output_budget` is a separate output/reasoning dimension and returns advice only. It
preserves explicit client output/reasoning controls, returns no caps for providers
that do not declare adaptive-control support, leaves quality-sensitive requests
unbounded, and stays unbounded while existing conciseness is disabled. The
request mapping is never mutated. Provider support must come from the selected
adapter's known capability, not an assumption based on model name.

## Measurement and gates

`ATBAMetrics` keeps input/output token observations, cost, latency, retries,
escalations, classifier/policy overhead, and task success distinct. Cost used in
paired comparisons must include retries/escalations and measured policy overhead;
latency should include policy overhead too. `evaluate_paired_sessions` fails
closed for incomplete/malformed pairs and marks evidence eligible only with at
least 100 paired sessions, net cost improvement, and no more than 3 percentage
points task-success regression. This is a mechanical gate, not a substitute for
reviewing population balance, quality rubric, provider capability, or actual
observed metrics. Synthetic unit-test rows are not shadow evidence.

No 100-session real shadow corpus or paired treatment run is checked into this
change, so there is no empirical improvement claim and no basis to enable
`v21_atba_enforce`. Collect and review real paired evidence before enforcement.
