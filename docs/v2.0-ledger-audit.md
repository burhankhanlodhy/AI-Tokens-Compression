## Decomposition invariants (AC-V2-4) — row level

The lanes are structurally disjoint columns: `cache_savings` (proxy-detected
exact/semantic hits), `l1_savings` (stripped tokens), `tool_compression_saved`
(bounded component estimate), and the new `provider_cache_read_tokens`/
`provider_cache_write_tokens` (measured provider facts) never merge in the
write path. NULL-vs-0 semantics keep AC-V2-6 honest: NULL = provider returned
no cache usage evidence; 0 = provider reported usage showing zero cached
tokens. Pricing stays out of the ledger — any provider-cache dollar figure
derives at read time from measured tokens × provider rate (SUM-over-ledger
rule, AC-A6/A12); do not present token counts as dollar savings until that
rate table exists.
