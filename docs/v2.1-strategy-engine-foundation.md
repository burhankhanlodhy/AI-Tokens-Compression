# V2.1 strategy foundation

This foundation adds deployment-only V2.1 flags and a policy/telemetry contract. It does not invoke or modify any optimization stage: all existing request behavior remains controlled by the existing V2.0 code and flags.

## Server-side flags and observability

`v21_deferred_tools_enabled`, `v21_tocp_enabled`, `v21_idcp_enabled`, `v21_atba_enabled`, `v21_atba_enforce`, and `v21_mtcc_enabled` are Settings/environment controls. They default to false. Do not map request headers, query parameters, or body fields to these settings. `/api/strategies` is an admin-bearer-protected deployment audit view; it reports each V2.1 flag, version, default-off status, and fallback, along with read-only V2.0 lane flag state.

## Policy API

`proxy.strategy_engine.StrategyRegistry(settings).evaluate(PolicyContext(...))` returns one immutable decision per V2.1 lane: status, reason code, strategy version, fallback, flag state, and separately named evidence dimensions. The context is trusted server-side scope, not raw client metadata. For TOCP, IDCP, and MTCC, a decision falls back when tenant, API-key, or session scope is missing. Any lane falls back when its full-context/full-output escape hatch is requested. ATBA stays in `shadow` unless both its deployment flag and separate enforcement switch are on.

The registry is orchestration scaffolding only; lane implementations must preserve fallback output and must bind every read/write to the authenticated tenant + API-key scope + session. Opaque IDs are not authorization. Retrieval must check all three scope values against persisted records. Do not accept these identifiers from arbitrary user-controlled context when authenticated proxy scope is available.

## Telemetry and attribution

`record_decision(connection, decision, context, evidence=...)` writes to the DBA-provided `strategy_telemetry` table with tenant/key/session scope, decision, reason, version, flag, observed latency, and lane evidence. Telemetry is best-effort and failures fail open; missing scope is refused. Evidence fields keep input/output token observations, cache read/write use, avoided calls, retry count, and policy overhead separate. The telemetry table is not a savings ledger and contains no savings aggregate; request-ledger accounting remains the source of billable transform/cache/avoided-call attribution. Leave latency null if a lane did not measure it rather than substituting telemetry-write time.

## Lane integration points

- Deferred tools: evaluate before changing catalog behavior; retain exact eager schemas/provider fallback. Dimensions: catalog/search overhead, misses, retries.
- TOCP: gate over-cap output only; fallback is complete original output. Dimensions: before/after input, retrieval count, overhead.
- IDCP: gate incremental reads only; fallback is full file on stale/ambiguous context. Dimensions: before/after input, fallback count, overhead.
- ATBA: shadow-classifier and output/reasoning budget evidence remain separate; include classifier/policy overhead and retries. Enforcement is separately controlled and must stay off pending paired evidence.
- MTCC: keep recent turns verbatim; retain exact source retrieval; fallback is verbatim history. Dimensions: before/after input, retrieval count, overhead.
- Existing L1, conciseness, provider-cache, semantic-cache, and routing-discovery: registry reports their existing config state only. Their execution, defaults, attribution, and release gates are unchanged.

No market/research percentages are encoded as thresholds or defaults. All experiment evidence must compare same-population baseline/treatment and report combined outcomes directly; do not add overlapping component rates.
