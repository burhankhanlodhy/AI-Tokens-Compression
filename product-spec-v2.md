**Market reality (from Dev's research):** provider-native prompt caching (Anthropic ~90% cached-input discount, OpenAI ~50%) is eating the *soft-compression* value prop. Winning products are **caching-first, compression-second**. We will not beat Portkey/LiteLLM on gateway features.

**What we are building is a product, not the single-user tool:** multi-provider, a money-visibility dashboard, and — later — the multi-tenant/admin surface that makes it sellable.

## 3. Phase A scope (the gate — PM locks here once D1–D3 confirmed)

### PA-0 Postgres migration (D2 override — Phase A, Postgres-native)
- Migrate from SQLite to **Postgres in Phase A**; schema designed Postgres-first (no portable-dialect constraint).
- Multi-tenant Postgres schema: `tenants`, `api_keys` (hashed/scoped), `providers` (registry), `requests` (gains `provider_id`, `tenant_id`, `cache_status`, `cache_savings`, **NUMERIC** cost columns, FK constraints with `ON DELETE RESTRICT`).
- Indexes on `(tenant_id, ts)` and `(provider_id, ts)` for KPI time-bucket queries; expression/generated column for `date_trunc('day', ts)` time buckets.
- **Migration safety gate (QA, non-negotiable — AC-A11):** run against BOTH a populated SQLite-era dataset (backfill) AND a fresh Postgres install; verify backfill correctness, rollback/failure recovery, tenant/isolation integrity, and NUMERIC cost precision.

### PA-1 Multi-provider support (headline ask)
- Provider registry (`providers` table + config): **Anthropic, OpenAI, OpenRouter, xAI, Google, + local vLLM/Ollama** — adding a provider = a row, not a code change.
- Per-request routing by model string (`model="anthropic/claude-..."` auto-routes to Anthropic adapter).
- **Real adapter layer**, not URL swap: OpenAI-compatible shape and **Anthropic `/v1/messages` shape** (+ system-as-param).
- Per-provider auth handling; BYOK passthrough preserved.
- **Provider contract matrix (QA gate, non-negotiable):** request translation, streaming, tool calls, multimodal input, auth, retries, rate limits, provider-error normalization — for OpenAI, Anthropic, OpenRouter, xAI, and one local backend (vLLM or Ollama).

### PA-2 KPI / monitoring API
- `/api/kpis?bucket=hour|day|minute&from=...` returning time-bucketed `{overview, series, by_model, by_provider, latency{p50,p95,p99}}` — the single contract both the dashboard and the Prometheus path consume. **One source of truth; no client-side aggregation** (financial correctness).
- `GET /api/kpis` correctness is an explicit AC (see AC list).

### PA-3 Dashboard (charts)
- Four-tab dashboard per @ui-ux-engineer's IA: **Overview** (KPI cards + savings-over-time + spend-per-model donut), **Traffic** (req/s, latency percentiles, error rate, cache-hit gauge), **Providers** (per-provider spend/savings/cache/error sortable table), **Keys & Tenants** (Phase C placeholder).
- One shared component set: big numeral + delta arrow + sparkline; **empty / loading / error** states carried from v1 AC-14/15/16. Dark theme. server-rendered + Chart.js CDN + single `dashboard.js`.
- **Cost-savings contract (B2-b — decomposition, NOT addend).** `cost_saved = est_cost_before − est_cost_after` **already contains** the L1 dollars; `l1_cost_saved` is the L1 *portion of* `cost_saved`, never a separate addend. Invariant, pinned per row and at the `total`, per-bucket, per-provider, and per-key levels: `0 ≤ l1_cost_saved ≤ cost_saved`, and `l1_cost_saved = 0` whenever `l1_tokens_stripped = 0`. **The headline savings KPI is `cost_saved` alone — never `cost_saved + l1_cost_saved` (that double-counts).** `l1_cost_saved` may render only as a breakdown/annotation *of* `cost_saved` (e.g. "of which L1 structural: $X"), in a stacked combo where the L1 slice is contained inside the total bar, and must be surfaced mutually exclusively with `cache_savings` per AC-A6.

### PA-4 Prompt caching orchestration (stack: exact-prefix only, Phase A/B)
- Detect cacheable static prefixes; send provider cache flags; **report cache-hit savings separately from compression savings** in stats (so the dashboard is honest and defies the native-caching critique).
- `requests` gains `cache_status` (miss/exact-hit) + `cache_savings` (Postgres hash lookups, not SQLite).

## 5. Acceptance criteria (Phase A — expanded for QA; QA's flags are codified)

- AC-A1. Registry supports all 6 providers; adding a provider requires no code change (config/row only).
- AC-A2. `model=` string auto-routes to the correct provider adapter; unknown provider → clear 4xx, no crash. **Routing semantics (ratified in B-21a, impl `9faa66a`):** routing sits behind `PROVIDER_ROUTING` (off by default — live traffic unaffected). When enabled: bare/unclaimed model names resolve to the documented default provider; a explicit `slug/model` naming an **unregistered** slug → **400 `{type:"unknown_provider"}`**; a known provider prefix whose provider is disabled/absent → **400** (never a silent reroute); Anthropic-shaped traffic never lands on an OpenAI-compat upstream. Known edge, tracked with B-21 (AC-A1 × AC-A2): `PREFIX_ROUTES` is a code constant, so a **config-added** provider (AC-A1's "row-only, no code change" path) has no prefix entry and its explicit `slug/model` currently falls through to the default — to be closed by routing a registered-but-prefixless slug to its own adapter.
- AC-A3. **Contract matrix passes.** All registry providers are tested *through their adapter class*: one parametrized `OpenAICompatAdapter` suite covering OpenAI/OpenRouter/xAI/Google/vLLM/Ollama (parameterized over auth_style: bearer / x-api-key / query-param / none, and model-route prefix) + a separate Anthropic suite. Across: streams, tool calls, multimodal, auth, retries, rate limits, error normalization. (QA-owned suite; recorded fixtures, no network in CI.)
- AC-A4. Anthropic requests use `/v1/messages` + system-as-param; OpenAI-compatible shape unchanged for OpenAI/OpenRouter/xAI.
- AC-A5. KPI API: `/api/kpis` returns the documented JSON contract; **numbers reconcile exactly to the Postgres `requests` ledger rows** (no drift). QA asserts financial-arithmetic correctness.
- AC-A6. Cache-hit savings are reported **separately from** compression savings in both KPI API and dashboard.
- AC-A7. **Tenant/key isolation & KPI selector contract (B-6a, ratified against implementation at `token-saver/proxy/kpis.py`, committed `7f2d102`).** `/api/kpis` accepts two **optional** query params, `tenant_id` and `api_key_id`. They are resolved on the route wrapper and threaded into `_fetch_kpis`, where they contribute to the ledger `WHERE` clause **before** every aggregate — so the `overview`, `series`, `by_model`, `by_provider` **and** `latency` groups are all scoped by the same selection (verified in code: the `where` is built once at the top of `_fetch_kpis`, lines 45–54, and reused by every query). Semantics (the agreed, shipped shape): **both absent** = aggregate across **all** tenants (admin/overview view); **present but unknown id** = **empty scope** — 200 with zeroed aggregates, *not* a 400 (an empty scope must never be readable as, nor turn into, cross-tenant data); **both present** = intersection (rows must match *both* `tenant_id` AND `api_key_id`). Scope is asserted **before** aggregation so no client-side filtering can leak rows. Per-tenant/per-key views return only that tenant's data; no cross-tenant leakage in any group. (Secret redaction on any key event logs, per AC-A13.) QA asserts: all-tenants = Σ tenants' rows; unknown tenant → zeros; a single tenant's overview/series/by_model/by_provider/latency all match the 1-tenant seed, and `api_key_id` narrows `tenant_id` further.
- AC-A8. Dashboard: four tabs render; every chart/card maps 1:1 to the KPI API (no client-side aggregation); empty/loading/error states behave per v1 AC-14/15/16.
- AC-A9. Graceful provider failure: upstream timeout/5xx → normalized error + metric, not a crash.
- AC-A10. Concurrency: Postgres handles concurrent `/v1/*` + dashboard + KPI calls with no lock contention (SQLite WAL no longer applies post-migration).
- AC-A11. **(Migration release gate, QA)** Migration tested on populated SQLite-era data AND fresh Postgres: backfill correct, rollback recovers, tenant FK isolation holds. **Cost precision contract:** cost columns are stored as `NUMERIC(14,8)`; Postgres rounds stored costs to 8 decimal places ($0.00000001 — far finer than any real cost measurement). **Drift bound stated as a function of row count, not just "8 decimals":** per-row quantization rounds to at most ±0.5e-8, so on a ledger of N rows the worst-case accumulated absolute drift is **N × 0.5e-8 USD** (e.g. 10M rows ≈ $0.05 — acceptable for this release; state it as such). The approved verification compares cost sums **at NUMERIC(14,8) quantized scale** — this is the explicit contract, so "no drift" means *no drift beyond the row-count-scaled quantization bound*, documented and tested as such (already implemented + documented by Dev). Legacy REAL float-artifacts (e.g. `0.30000000000000004`) verify equal after quantization. If finer precision than 1e-8 USD were ever needed, that scale bump would be a separate reviewed change; it is not required for this release.
- AC-A12. **(Financial trust, QA)** `/api/kpis` totals and every time bucket reconcile **exactly** to the request-level ledger rows in Postgres — no drift; QA ledger-reconciliation suite is a release gate.
- AC-A13. Secret handling (Postgres-native): API keys stored only as hashes (in `api_keys`); no raw keys in DB, logs, or error bodies.

Do not restart the container on a swapped image before the cutover procedure has run.
- **AC-PC2. `semantic_cache_entries` table (DBA owns).** A **separate** table from the hot exact-prefix table, keyed on: `tenant_id`, provider/model, embedding model + dimension + version, canonical-prompt hash, **`request_parameters_hash`** (shipped shape; `361d1ec` — the PC3 seam requires all mandatory scope keys present before lookup, and this field carries the parameter scope), response reference (`response_ref`), expiry, `quality_version`, and hit metadata. HNSW cosine index (pinned to `vector(1536)` — HNSW requires a fixed dimension; changing embedding dimension is a reviewed table/index migration, never mixed-dimension inserts, per DBA `361d1ec`); results are written back to the ledger with `cache_status = 'semantic_hit'` — the literal is **already pinned** by `postgres-schema-v2.sql` `chk_cache_status` (`IN ('miss','exact_hit','semantic_hit')`); no alternate spelling. Attribution stays on the existing ledger (AC-A6 separation holds: semantic savings are cache savings, never compression).
  - **Response store contract (PM, ratified 2026-09-19):** cached responses live in **Postgres, same database** — no external resolver or second service, extending the D3 one-transactional/backup-boundary rationale to payloads. New migration `token-saver/migrations/20260919_pc2_semantic_responses.sql` adding `semantic_cache_responses`: `tenant_id` FK → tenants (ON DELETE CASCADE), `response_ref` TEXT with `UNIQUE (tenant_id, response_ref)` (tenant-scoped, same as entries), `payload` JSONB, `schema_version` INT (v1), `sha256` TEXT (integrity), `content_length` INT, `created_at`, `expires_at` TIMESTAMPTZ NOT NULL aligned to the entry's expiry. The writer inserts the **entry + response pair atomically in one transaction**; the AC-PC3 delete-then-reinsert supersession contract covers BOTH tables (delete old pair, insert new pair). A dangling/missing `response_ref` is a **cache miss — never a raise** — with lazy cleanup of the orphan pair, per the "cache must never break the proxy path" discipline.
  - **Hit shape (same ruling):** cache **non-streaming completions only** (`stream: false`); `payload` = the provider's OpenAI-compatible response body exactly as the proxy relays it (`schema_version = 1` = relayed-as-received; no re-shaping until response re-shaping lands). A hit replays the stored body verbatim as a non-streaming response; streamed requests are misses by construction. NOTE: the Phase A exact cache stores **no** response bodies (`caching.py` — "Phase A does NOT synthesize responses locally … response storage" is deferred) — semantic caching is the **first response-storing cache**; there is no existing pattern to reuse.
  - **TTL/retention/size/PII (same ruling):** the one AC-PC3 TTL knob governs entry + response expiry together; expired pairs are purged (writer-side sweeper or lazy delete on write); no separate retention policy in v1. Responses over `SEMANTIC_CACHE_MAX_RESPONSE_BYTES` (default **1 MiB**) are NOT cached (miss) — never truncated, never a failure. Payloads are tenant-scoped data in the tenant's own Postgres under the existing trust model (ledger-class, AC-A13 discipline); no separate PII pipeline in v1.
- **AC-PC3. Lookup seam, mandatory filters (Dev owns).** Semantic lookup uses HNSW cosine search **with mandatory tenant/provider/model/parameter filters** — a query without all filters present must not run. Thresholds are calibrated (not hardcoded guesses). The seam sits behind the existing config-flag pattern with semantic caching **off by default** (AC-PC5) so the proxy path is unchanged until the gate passes.
  - **Invalidation ruling (PM, ratified 2026-09-19, committed `66c2ef4`):** expiry is the **sole automatic** invalidation path in v1 — the seam's strict `AND expires_at > now()` gate (`proxy/semantic_cache.py:119`) is the deterministic mechanism (AC-PC4.3). No faster-than-expiry automatic mechanism ships in v1: cache identity pins tenant/model/embedding/request-params, so the only staleness window is content drift inside the TTL — a tokens-vs-correctness tradeoff, not a leak. Deterministic-invalidation gates assert this exact boundary.
  - **Writer supersession contract (PM, same ruling):** any write that supersedes an existing identity MUST be **transactional delete-then-reinsert in one commit** — proven deterministic by QA's pgvector gates (delete+reinsert retargets the hit; in-place supersession raises UniqueViolation on the identity unique index and is a bug). No new invalidation index or endpoint.
  - **TTL knob (new work in the writer commit):** TTL is a **config knob** with a conservative v1 default, tuned on traffic data later (calibrated-not-guessed discipline, same as the threshold). Known gap as of 2026-09-19: zero `ttl`/`expires` entries exist in `proxy/config.py` — the knob ships with the C-1 writer alongside the `ef_search` HNSW-safety pin.
  - **Embedding contract (PM, ratified 2026-09-19):** embeddings come from an **OpenAI-compatible `/embeddings` endpoint using the SAME configured provider credential the proxy already holds** (per-provider BYOK/native key — no new auth surface, no new secret). Model = `EMBEDDING_MODEL` env var, default `text-embedding-3-small` (exactly **1536 dimensions**, required by the AC-PC2 `CHECK (embedding_dimensions = 1536)` and HNSW `vector(1536)` pin); a different-dimension model is a config error, refused pre-query (QA gate). Embedding input = the same canonicalized request that produces `canonical_prompt_hash`. **Failure path: any embedding error (network, auth, unsupported endpoint, dimension mismatch) → clean cache miss, no raise, no upstream call skipped** — the request passes through exactly as if semantic caching were off (AC-PC5 behavior preserved on failure too).
- **AC-PC4. QA gate (non-negotiable — nothing ships before this is green).** @qa-lead asserts all of: (1) **no cross-tenant hits** — tenant/provider/model filters enforced; a prompt in tenant A can never resolve a `semantic_cache_entries` row from tenant B (build the cross-tenant probe explicitly); (2) **false-hit-vs-miss calibration** — thresholds validated on a committed corpus (misses vs false hits documented, not just accuracy on happy-path); (3) **deterministic invalidation** — invalidation (expiry, response ref change) is deterministic and reproducible, matching AC-P1d cache-stability discipline; (4) **`EXPLAIN`/latency benchmarks** — filtered HNSW query plans use the index (no seq scan over the vector table at traffic shape) with latency bounded and recorded before enablement; (5) attribution: `semantic_hit` rows carry correct `cache_savings`, never double-counted with L1 (AC-A6 / B2-b decomposition contract). **Prerequisite (PM 2026-09-18):** a **pgvector-backed CI lane or migration-applying fixture** must exist before the gate can run — the current 634-green proves bootstrap stock-safety only, and PC1/PC2 DDL is executed by zero automated tests today (`test_semantic_cache.py` is 5 seam-level tests with the flag off); the cross-tenant probe and EXPLAIN gate cannot be asserted in an environment where the extension is absent. This lane is a prerequisite to the gate, not part of the gate's scope.
  - **Threshold ratification rule (PM, ratified 2026-09-19, committed `66c2ef4`):** the committed calibration-corpus threshold (currently **0.12**) is **provisional — gate mechanics only**. The production value stays AC-PC4 scope: ratified by @product-manager from @database-administrator's false-hit-vs-latency tradeoff curve measured at **traffic-shaped volume** (the post-writer rerun on real `semantic_cache_entries` row volume; the disposable-20k probe is evidence for the plan shape, not the number). Bias is **conservative (lower end of the curve)**: a false hit serves the wrong cached response — a correctness bug — while a miss only costs tokens. No enablement before ratification; AC-PC5 holds regardless.
- **AC-PC5. Off-by-default until gate green (product contract).** Semantic caching ships **disabled** in the production config; the QA gate (AC-PC4) is the release gate that flips it on. No client request can self-enable it (same discipline as the P6 dose pin). Marketing copy must not claim semantic caching before AC-PC4 is green.

### Phase C-2 — Keys & Tenants admin surface (write-endpoint auth gate; ratified @product-manager 2026-09-19)

> **Decision record (B-hyg2; source of record `keys-tenants-tab-spec.md` §3 + §4.5, committed `235b2b3`).** All **four write endpoints** — `POST /api/keys`, `POST /api/keys/{id}/rotate`, `POST /api/keys/{id}/revoke` — require `Authorization: Bearer <token>`. Token source: `ADMIN_TOKEN` env var when set; otherwise generated at boot and **printed once to the proxy's startup log** (boot-printed, never persisted to disk, never re-printed). Missing/invalid token → **401** with the proxy's existing error shape. Read endpoints (`GET /api/tenants`, `/api/keys`, `/api/kpis`, `/dashboard`) stay **unauthenticated** for Phase C under the self-host trust model. Rationale (ratified): the proxy is network-facing by definition, so unauthenticated create/rotate/revoke lets anyone who can reach the dashboard mint keys that spend the owner's budget or revoke their own keys; full admin auth (accounts/sessions) is deferred scope. QA gates the write endpoints behind this.
- **UI consequence (§4.5, boarded with the spec).** The browser holds the token in a JS module variable only — never storage APIs, never URLs, never logs; the first 401 on a write renders an inline masked entry form ("Printed once to the proxy's startup log at boot"); a mid-session 401 (proxy restart → new boot token) clears it and re-prompts with "Token rejected — the proxy may have restarted" while preserving the pending action's confirm state. The flow is identical whether the operator set `ADMIN_TOKEN` or relies on the boot print.
- **Implementation contract.** `.env.example` must carry `ADMIN_TOKEN=` (empty placeholder, same pattern as `POSTGRES_PASSWORD=`) **in the same commit as the §3 write endpoints** — never land the endpoints without the documented variable.
- **QA gate (spec §6 gate 6).** Write-path auth: header attached only after token entry, token absent from DOM/storage/URLs/logs at all times, a 401 re-prompt does not lose the pending confirm state.
